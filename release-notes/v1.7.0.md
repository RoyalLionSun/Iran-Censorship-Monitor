## Iran Censorship Monitor v1.7.0

v1.7.0 operationalizes the existing Iran ASN inventory and secondary topology enrichment as a bounded local coverage snapshot, same-origin API and analyst review dashboard. It does not add a new censorship sensor, a dashboard-time upstream crawler, or any independent censorship vote.

### Operational ASN coverage snapshot

- adds operator-triggered persistence with `node scripts/fetch-iran-asn-inventory.mjs --write` to `var/asn-coverage/latest.json`;
- keeps the complete RIPE/RIR-associated Iran ASN inventory separate from the curated monitoring catalogue;
- persists only bounded coverage/provenance fields plus at most 100 prioritized uncurated review candidates, not the complete ipverse world dataset or full enrichment record set;
- validates schema version, `IR` scope, timestamps, internal count consistency, SHA-256 provenance, candidate uniqueness/class bounds and zero-vote semantics;
- distinguishes `observed`, `stale`, `no_data` and `error`; missing data is never converted to zero Iran ASNs;
- writes through a temporary file followed by rename so normal runtime does not consume a partially written snapshot.

### Local API and dashboard

- adds `GET /api/asn-coverage`, which reads only the fixed local snapshot and performs no RIPE or ipverse network request;
- exposes RIR-associated inventory size, country-level RIPE registered/routed counts, curated catalogue coverage, ipverse metadata coverage, snapshot age and a bounded review queue;
- adds the `Coverage and review queue` dashboard panel and real Headless Chrome coverage for its observed-state rendering;
- review classes remain analyst-prioritization hints only and are not censorship scores, importance scores or automatic operator classifications;
- RIR association, RIPE RIS routing visibility and ipverse topology metadata remain separate evidence dimensions.

### Live RIPEstat compatibility hotfix

- v1.7 runtime acceptance exposed that the live RIPEstat `country-resource-list` response could omit the documented `data.resource` echo while still returning the requested `IR` resource data;
- the request remains hard-scoped with `resource=IR`;
- the parser now tolerates only the missing resource echo, still rejects every explicit non-IR resource and still requires `data.resources.asn`;
- deterministic regression coverage reproduces the observed live response shape and preserves fail-closed handling for malformed data.

### Actions efficiency

- routine CI no longer runs on feature-branch pushes;
- normal CI runs on pull requests to `main`, pushes to `main`, `v*` tag pushes and explicit manual dispatch;
- operator-triggered RIPE/ipverse snapshot generation remains outside routine Actions and the large ipverse dataset is never downloaded by the normal CI path;
- this preserves PR and production verification while avoiding the previous redundant feature-branch CI run.

### Deployment boundary

v1.7.0 does **not** authorize an Iran Fleet Stage-1 pilot, active circumvention/protocol probing, or automatic censorship attribution. Repository policy remains `deploymentAuthorized:false`.

Registry identity, RIR country association, RIPE routing visibility, topology metadata, candidate priority and contextual reporting add zero independent censorship votes. `no_data`, `partial`, `token_required`, stale and error states remain explicit and cannot be converted into successful measurements, zero incidents or national availability/censorship verdicts.

Before any real Iran pilot, the existing external gates remain mandatory: isolated Linux/systemd sandbox and negative-egress validation, real project-controlled Class-A endpoints and collection edge, out-of-band key provisioning/rotation/revocation, rollback exercise, voluntary informed operator consent/withdrawal and explicit deployment authorization.
