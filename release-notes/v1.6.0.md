## Iran Censorship Monitor v1.6.0

v1.6.0 is the next published release after v1.4.0. It includes the repository changes developed during the unpublished v1.5 line as well as the v1.6 shutdown-context work.

### Iran ASN identity and inventory

- replaces ad-hoc provider completeness assumptions with a registry-qualified curated monitoring catalogue;
- separates canonical RIPE registry identity, operational/business aliases and explicit operator-family grouping;
- adds Fanap Telecom / ZiTEL AS206065 (`FDI`) and AS24631 (`FANAPTELECOM-FCP`) as distinct routing identities under one operator family;
- separates the curated catalogue from the complete RIR-associated Iran ASN population obtained through RIPEstat `country-resource-list`;
- keeps RIPEstat registered/routed country-level counts separate from ASN-by-ASN routing claims;
- adds operator-triggered CC0 `ipverse/as-metadata` enrichment with byte bounds, SHA-256 provenance and transparent review classes;
- registry, inventory and topology metadata remain context only and cannot create censorship votes.

### Current shutdown context

- hardens the token-gated Internet Society Pulse shutdown adapter with explicit Iran identifiers, timestamp validation, selected-window overlap semantics and open-ended-event handling;
- preserves Pulse verification level, type, cause, affected regions and source provenance;
- keeps Access Now #KeepItOn STOP as historical curated context, with the currently published corpus documented through 2025;
- adds deterministic STOP/Pulse candidate correlation only when time intervals overlap and both records normalize to the same broad scope class;
- every candidate remains `possibleSameIncident:true`, `automaticMerge:false` and `independentTechnicalVote:false`;
- no temporal correlation becomes incident identity, causality, mechanism, intent or an additional technical sensor vote.

### Dashboard and context export

- renders Pulse status and incidents in the Intelligence panel, including explicit `token_required`, `no_data`, observed and error semantics;
- renders conservative STOP/Pulse review candidates while keeping source provenance separate;
- extends the context CSV with Pulse status/events and STOP/Pulse correlation candidates;
- missing Pulse credentials are exported as `matched=not_inferred`, never as zero incidents;
- adds deterministic export tests and keeps the real Headless Chrome presentation gate for the complete context path.

### Deployment boundary

v1.6.0 does **not** authorize an Iran Fleet Stage-1 pilot or active circumvention/protocol probing. Repository policy remains `deploymentAuthorized:false`.

RIR country association, registry identity, routing visibility, topology metadata, curated shutdown records and source correlation remain separate evidence dimensions. Missing/partial/error/token-required states are never converted into successful measurements, zero incidents or national availability/censorship verdicts.

Before any real Iran pilot, the existing external gates remain mandatory: isolated Linux/systemd sandbox and negative-egress validation, real project-controlled Class-A endpoints and collection edge, out-of-band key provisioning/rotation/revocation, rollback exercise, voluntary informed operator consent/withdrawal and explicit deployment authorization.
