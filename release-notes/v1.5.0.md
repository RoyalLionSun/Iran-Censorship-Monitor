## Iran Censorship Monitor v1.5.0

v1.5 hardens the Iran ASN scope and replaces ad-hoc provider-list completeness assumptions with a reviewed identity model plus a separate programmatic country inventory.

### Registry-qualified ASN identities

- corrected stale or misleading curated ASN labels against current RIPE registry objects;
- removed AS35718 from the Iran scope after current registry evidence identified it as a Russian network;
- separated canonical registry identity from operational/business aliases;
- made the TCI vs TIC/Zirsakht naming collision explicit and kept ITCO/DCI separate from TIC;
- introduced `operatorFamily` grouping so multiple ASNs operated by one organization cannot be mistaken for independent operators or independent censorship evidence;
- expanded reviewed Iran topology/access coverage with TIC/Zirsakht, IPM, Shatel, Asiatech, Sabanet lineage, Datak, Pishgaman, Afranet, Respina and AbrArvan.

### Fanap Telecom / ZiTEL

- added AS206065 (`FDI`) and AS24631 (`FANAPTELECOM-FCP`) as separate reviewed ASN profiles;
- preserves Fanap Telecom / ZiTEL operational aliases while retaining current registry organization `ORG-PNEV1-RIPE`;
- groups both under `operatorFamily: fanap-telecom`;
- only the reviewed AS206065 access profile participates in the provider comparison, preventing double weighting of the same operator family.

### Registry drift validation

- added a bounded direct RIPE Database REST `aut-num` validation path for curated profiles;
- hard checks cover ASN, `as-name`, organization handle and authoritative `ASSIGNED`/`LEGACY` status;
- registry identity failures remain hard errors rather than silently accepted metadata drift;
- registry/topology identity remains context only with `independentCensorshipVote:false`.

### Complete Iran ASN inventory boundary

- `data/asns.json` is now explicitly documented as a curated monitoring/topology catalogue, not a complete list of all Iran-associated ASNs;
- added an operator-triggered RIPEstat `country-resource-list` inventory using RIR Statistics country association as the canonical completeness population;
- added separate RIPEstat `country-asns` level-of-detail 0 registered/routed counts with returned RIS time semantics;
- registered country association, routed control-plane visibility, curated monitoring membership and censorship evidence remain separate dimensions;
- no undocumented `lod=1` response shape is guessed and no ASN-by-ASN routed set is fabricated from country-level counts;
- curated ASNs that drift outside the current RIR-associated inventory are surfaced explicitly.

### Secondary topology prioritization

- added on-demand CC0 `ipverse/as-metadata` enrichment after the RIPE/RIR inventory establishes country scope;
- preserves secondary `category`, `networkRole`, prefix/connectivity statistics, provider/customer/peer data, degree, reach, `lastAnnounced` and change timestamps;
- SHA-256 anchors the exact downloaded ipverse bytes and enforces a bounded download ceiling;
- ipverse country disagreement is reported as a data-quality finding and never overrides the canonical RIR inventory;
- analyst candidates are ordered by transparent review classes (transit, access, strategic service, topology-observed, long tail) and deterministic topology metadata rather than an invented censorship-likelihood score;
- the large world metadata dataset remains operator/on-demand input and is not downloaded by routine GitHub Actions.

### Deployment boundary

v1.5 does **not** authorize an Iran Fleet Stage-1 pilot or active protocol/circumvention probing. Repository policy remains `deploymentAuthorized:false`.

ASN registry identity, country association, routing visibility, prefix/address scale, topology relationships and commercial rankings are context dimensions only. They do not establish end-user reachability, filtering behavior, censorship mechanism or intent, national shutdown state, NIN status, province location or SIM entitlement class.

Before any real Iran pilot, the existing external gates remain mandatory: isolated Linux/systemd sandbox and negative-egress validation, real project-controlled Class-A endpoints/collection edge, out-of-band key provisioning and rotation/revocation exercise, rollback exercise, voluntary informed operator consent/withdrawal, and explicit deployment authorization.
