## Iran Censorship Monitor v1.9.1

v1.9.1 collects the security, privacy and presentation fixes made after v1.9.0. It needs Node.js 22.13 or newer; v1.9.0 stated 20.11, which could not start the server (`node:sqlite`).

### Security and privacy

- the protected on-demand Globalping check asks no more than the collector: a DNS lookup or an HTTPS `HEAD` request of one of the allowed services, from one network registered in Iran; other targets, measurement types and networks are refused;
- the Globalping probe inventory is published as counts per network, without a probe's city, coordinates, resolvers or tags;
- links that are stored or sent to others (feed, open data, reports, Telegram posts) no longer follow the request's `Host` header; every page carries the same security headers; unexpected internal errors no longer reach the reader;
- networks registered to a private person appear by number everywhere, except a network that still carried traffic during a nationwide shutdown: the shutdown timeline names the registrant the RIPE Database recorded at the time, as a registry fact next to the measurement;
- bounded per-visitor budgets, a shutdown timeline that never holds up the Overview for more than ten seconds, and a request log without query strings.

### Findings and reports

- change alerts: a nationwide outage beginning or ending, or a main service turning blocked or reachable across Iran, becomes a feed entry (and a Telegram post, if set up) once a second check confirms it;
- an outage still under way is headed with its day ("since … · day n");
- weekly and monthly reports link Filterwatch's expert reports of their period as context;
- "blocked in N of M networks" classifies each network by the same majority rule as the per-network table;
- the latest disruption is named in plain words, with its length and Tehran time.

### Presentation

- Technical analysis in an aligned two-column grid; cards without data for the selection shrink to their title and reason; charts drawn at their shown width;
- Overview boxes aligned: filter fields of one height, equal-height answer boxes, four ways around the filter per row, two-line access rows, source links at the bottom of each card.

### Operation

- `/api/health` and `BUILD.txt` name the commit a server runs;
- the offline copy finishes saving and trimming before the browser may stop its worker;
- CI runs on Node.js 22.13.0 and the current 22 release; a page-weight budget and commit-message checks guard every commit.

### Verification

- `npm run check`: syntax checks and all deterministic tests pass, including checks that versions, the test count and links in the documents are current;
- `npm run verify:release-notes`, `npm run build` and the headless browser gates (`npm run verify:ui`) pass;
- GitHub CI passes on Node.js 22.13.0 and 22;
- details and counts: `docs/VERIFICATION.md`.

### Deployment boundary

This release does not authorize an owned probe fleet in Iran; `deploymentAuthorized:false` remains. Active checks from RIPE Atlas and Globalping stay off unless an operator switches them on, and never target news, opposition or circumvention sites. Before hosting the dashboard publicly, work through `GO_LIVE.md`.
