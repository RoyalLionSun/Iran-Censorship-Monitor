## Iran Censorship Monitor v1.3.0

v1.3 adds topology and route-origin integrity context while preserving the strict separation between infrastructure observations and censorship evidence.

### CAIDA ASRank topology context

- Added selected-ASN CAIDA ASRank context.
- Shows AS rank, customer-cone size, degree and inferred AS relationships.
- Preserves provenance overlap with CAIDA Ark, Route Views and RIPE inputs.
- ASRank therefore cannot artificially increase the number of independent routing sources.
- ASRank remains context-only and has no independent censorship vote.

### RPKI / route-origin integrity

- Added RIPEstat RPKI validation for bounded currently announced prefixes.
- Added bounded monthly IPv4/IPv6 VRP history.
- Preserves the upstream states:
  - `valid`
  - `invalid_asn`
  - `invalid_length`
  - `unknown`
- RPKI validity is not converted into censorship intent, hijack attribution or user-level reachability conclusions.

### Circumvention-source review

- Re-reviewed Psiphon and Ceno/eQualitie as potentially valuable Iran circumvention/resilience sources.
- No synthetic or scraped telemetry was introduced where no stable supported machine-readable Iran time-series API could be established.
- Reports and articles remain dated contextual evidence rather than technical sensor votes.

### Dashboard

- Added dedicated CAIDA ASRank and RIPEstat RPKI panels.
- Kept topology and route-origin information separate from censorship assessment and source-family voting.
- Expanded real headless-Chrome presentation verification to include ASRank and RPKI alongside the existing M-Lab, APNIC and Access Now STOP panels.

### Verification

- Deterministic suite expanded to **211 tests**.
- Post-merge production CI passed **211/211** tests.
- Production build, headless browser gate, secret/private-key scan and runtime smoke test passed.
- Live acceptance passed for:
  - CAIDA ASRank
  - RIPEstat RPKI
  - RIPE RIS Live
  - Route Views via CAIDA BGPStream

### Deployment boundary

v1.3 does **not** authorize an Iran Stage-1 probe deployment.

`partial`, `no_data` and error states remain explicit and can never become national or provincial availability verdicts.

External systemd/egress validation, controlled production endpoints, key management, rollback validation, voluntary operator consent and explicit authorization remain mandatory.
