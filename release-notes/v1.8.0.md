## Iran Censorship Monitor v1.8.0

v1.8.0 adds a plain-language current-situation layer and a controlled English/Farsi dashboard experience while preserving the existing measurement, evidence-independence and deployment boundaries. It does not add a censorship sensor, change source scoring, authorize active deployment, or translate arbitrary external-source content.

### Plain-language current situation

- adds a prominent current-situation summary derived only from the existing reviewed `assessment` / `publicSummary` contract rather than a second scoring system;
- distinguishes insufficient data, no corroborated major disruption, one-source elevated signal, corroborated disruption and strong multi-source disruption;
- explains what each state means and, critically, what it does not establish;
- surfaces the most important supporting signals plus control-plane/data-plane divergence without converting BGP visibility into end-user Internet availability;
- never treats absence of a detected major disruption as proof that Internet access is fully normal;
- never claims a complete nationwide shutdown from the current assessment model.

### English/Farsi and RTL foundation

- adds central versioned English/Farsi locale composition and a persistent `EN | فارسی` language switch;
- applies `lang=en/dir=ltr` and `lang=fa/dir=rtl` deterministically;
- translates controlled static labels, status text, explanations, historical v11-v17 context panels and whitelisted dynamic runtime sentence frames;
- preserves arbitrary external-source titles/content verbatim instead of applying runtime Google, DeepL, AI or other machine translation;
- keeps ASN identifiers, IP addresses/prefixes, BGP paths, URLs, timestamps and other technical values direction-safe/LTR where appropriate;
- preserves variable technical values while translating only their controlled UI framing.

### Explanatory dashboard UX

- adds concise `What this means` explanations to high-value measurement and context panels;
- retains raw/source-specific values, provenance links and technical drill-down below the plain-language layer;
- keeps `no_data`, `partial`, `token_required`, stale and hard-error states explicit rather than translating them into successful/zero observations.

### Deployment boundary

v1.8.0 does **not** authorize an Iran Fleet Stage-1 pilot, active circumvention/protocol probing, automatic censorship attribution, nationwide availability claims or province/SIM-class inference. Repository policy remains `deploymentAuthorized:false`.

No new independent censorship vote is introduced. BGP visibility remains control-plane context rather than proof of working end-user Internet; contextual sources and translated presentation text cannot increase corroboration. Missing, partial, token-required, stale and error states retain their existing fail-closed semantics.

Before any real Iran pilot, the existing external gates remain mandatory: isolated Linux/systemd sandbox and negative-egress validation, real project-controlled Class-A endpoints and collection edge, out-of-band key provisioning/rotation/revocation, rollback exercise, voluntary informed operator consent/withdrawal and explicit deployment authorization.
