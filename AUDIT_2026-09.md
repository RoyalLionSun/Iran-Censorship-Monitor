# Audit, 24 September 2026 — what modern dashboards do better, and what we changed

Scope: the whole page (Overview, Technical analysis, header/footer, export), measured on the
running server and in a real browser (headless Chrome), English and Farsi.
Comparison: Cloudflare Radar, OONI Explorer and current practice for web apps that must work on
poor connections.

## Measured before → after

| | Before | After |
|---|---|---|
| Page files (scripts, styles, texts) per visit | ~600 KB | **153 KB** (Brotli) |
| Overview answer | 570 KB | **42 KB** |
| Domain list answer | 496 KB | ~33 KB |
| Returning visit, unchanged files | full reload | **0 bytes** (ETag → 304) |
| Without connection | error / empty page | **last copy of the same view, dated** |
| Link shared on Telegram/WhatsApp/X | bare link | **preview image and text (EN + FA)** |
| Phone users (most readers in Iran) | Export menu hidden | **PDF/Word reachable** |
| First visit from a Persian browser | English | **Farsi** |

Text contrast was already fine: every text colour reaches WCAG AA (≥ 4.5:1; weakest 5.1:1).

## Done in this audit

1. **Compression and caching** (`lib/common.mjs`, `server.mjs`): Brotli or gzip for answers and
   files, compressed once per file version; ETags so unchanged files cost nothing.
2. **Offline copy** (`public/sw.js`): online, every request goes to the network, so the page is
   always fresh; the answers are only kept. Without a connection the last copy of *exactly the
   same view* is shown with a notice and its date. A different network or period is never
   answered with another view's data. Tested with the server stopped.
3. **Link previews**: Open Graph / Twitter tags and a header-style preview image
   (`public/brand/og-image.png`, English and Farsi). Set `PUBLIC_URL` when online, because
   previews need absolute image addresses.
4. **Installable app**: web app manifest, icons (including a maskable one), theme colour.
5. **Accessibility**: skip link, respect for "reduce motion", one main heading per page, named
   buttons in the URL details.
6. **Footer mirrors the header** (the header is the design reference).
7. **Farsi**: Persian digits in the technical view; Persian browsers open in Farsi.

## Proposals, not built (need a decision)

Ordered by value for readers in Iran and effort.

1. **Reachability of the page itself from Iran** (before publishing). Hosting not only behind
   a provider Iran blocks, mirrors, an .onion address; after going online, test our own address
   from inside Iran (OONI Run link). *Already in the next steps.*
2. **"What changed" as a feed and channel.** Cloudflare Radar offers notifications on outages;
   we could publish our daily "What changed" as an RSS/Atom feed (tiny, no account) and,
   optionally, post it to a Telegram channel. Readers in Iran often reach Telegram through a
   VPN anyway. Effort: small (feed), medium (Telegram bot).
3. **Findings / monthly report.** OONI Explorer publishes "Findings", Cloudflare Radar quarterly
   summaries. Our Word/PDF export can produce a monthly report automatically (e.g. first of
   each month, both languages) that journalists can cite. Effort: medium.
4. **Share buttons** for Telegram, WhatsApp and X with a prepared sentence in the reader's
   language ("Instagram, WhatsApp … are blocked in Iran — measured today") and the view link.
   Effort: small.
5. **Embeddable status badge / widget** for news sites and NGOs, with our data under a free
   licence (Radar: CC BY 4.0). Effort: medium; needs a licence decision.
6. **Load only the reader's language** (today both dictionaries load, ~40% of text bytes).
   Effort: small.
7. **Faster first answer for a new view** (cold Overview 15–25 s while OONI answers):
   show connection tiles as soon as they arrive and the service tiles when OONI follows; in
   production, keep popular views warm. Effort: medium.
8. **Light mode** following the system setting (some readers and printing prefer it).
   Effort: medium (all colours are tokens already).
9. **Real-phone check** below 500 px width: the test browser here cannot go narrower, so the
   smallest phones are unverified.
10. **Automated accessibility test** (axe) in the browser gates, and production security
    headers (HSTS, Permissions-Policy) once hosting is chosen.
